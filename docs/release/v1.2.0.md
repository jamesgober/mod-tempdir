# mod-tempdir v1.2.0

**Security and correctness release. Upgrade recommended, especially on
Windows and macOS if you call `cleanup_orphans`.**

`NamedTempFile` now keeps the handle it created the file with, and
`persist_atomic` refuses to publish an entry that replaced it.
`cleanup_orphans` checks process liveness on every platform and never
removes the calling process's own entries. No signature changes; the
new API is additive.

## Security

- **`NamedTempFile` keeps its handle.** In 1.1.0 the handle from the
  exclusive create was closed at once, so every later write, the
  fsync in `persist_atomic` and the rename acted on whatever was at
  the path by then. In a directory that another user or service can
  write, that party could swap the file for a link (so the caller's
  write lands in another file) or for its own file (so
  `persist_atomic` publishes its content). Now:
  - writes through `as_file`, `as_file_mut` or the `Write` impl always
    reach the created file;
  - `persist_atomic` syncs through the held handle and checks that the
    path still names that file (device and inode on Unix, volume
    serial number and file index on Windows, never following a final
    link) before it renames; a mismatch fails with
    `io::ErrorKind::Other` and nothing is renamed;
  - `reopen` makes the same check.
  The rename still goes by name, so a short window remains between
  the check and the rename. Keep files that need full protection in a
  directory no one else can write.

## Fixed

- **`cleanup_orphans` deleted live entries on Windows and macOS.** The
  liveness check counted every process as dead off Linux, so any
  default-named entry older than the threshold was removed, including
  the calling process's own `TempDir`. Now:
  - entries with the calling process's PID are never removed;
  - other PIDs are checked with `kill(pid, 0)` on Unix systems other
    than Linux and with `OpenProcess` plus `GetExitCodeProcess` on
    Windows; Linux keeps `/proc/{pid}`;
  - an unclear answer (such as another user's process that cannot be
    queried) counts as alive;
  - a directory's age is the newest mtime of the directory and its
    direct children.
- `persist_atomic` to a bare file name (such as `"config.toml"`) now
  syncs the current directory after the rename. Before, the empty
  parent path made the directory sync fail silently.
- The crate's own tests no longer sweep the shared OS temp directory;
  they use `cleanup_orphans_in` on a private directory.

## Added

```rust
file.as_file()                          // -> &File
file.as_file_mut()                      // -> &mut File
file.reopen()                           // -> io::Result<File>
impl Read + Write + Seek for NamedTempFile
cleanup_orphans_in(dir, max_age_hours)  // -> io::Result<usize>
```

Write through the handle and persist:

```rust
use mod_tempdir::NamedTempFile;
use std::io::Write;

let mut tmp = NamedTempFile::new_in("/var/lib/app")?;
tmp.write_all(b"new contents")?;
tmp.persist_atomic("/var/lib/app/config.toml")?;
# Ok::<(), std::io::Error>(())
```

## Compatibility

- No public signature changed.
- A `NamedTempFile` now holds one open file handle for its lifetime.
  On Windows the handle allows other opens, renames and deletes, so
  opening the path, `Drop` and `persist_atomic` behave as before.
- `persist_atomic` now fails if the path no longer names the file the
  value created, for example if code removed the file and created a
  new one at the same path. Write to the existing file instead
  (through the handle, or by path, which keeps the same file).
- `cleanup_orphans` removes fewer entries on Windows and macOS: only
  those whose process has exited. On platforms with no process query
  (neither Unix nor Windows) it removes nothing.
- The crate now contains a few `unsafe` FFI calls (`kill`,
  `OpenProcess`, `GetExitCodeProcess`, `CloseHandle`,
  `GetFileInformationByHandle`) into libraries `std` already links. No
  runtime dependency was added.
- MSRV stays at Rust 1.75.
