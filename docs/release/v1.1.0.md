# mod-tempdir v1.1.0

**Security release. Upgrade recommended for every user.**

`mod-tempdir` now creates temp files exclusively with private
permissions, draws every name from the operating system's random
source, and rejects path separators in prefixes. It also adds `new_in`,
so an atomic persist can stay on one filesystem. No signature changes.

## Security

- **Exclusive creation.** Files are created with
  `OpenOptions::create_new` and directories with `DirBuilder`. Nothing
  that already exists at the chosen path is opened, truncated or
  followed; a taken path gets a fresh name (up to 64 attempts).
- **OS-random names in every build.** The 12-character name fragment
  carries 60 bits from the OS random source. The default build reads it
  through `std`; the `mod-rand` feature reads it through
  `mod_rand::tier3`.
- **Private permissions.** On Unix, files are `0600` and directories
  `0700`. On Windows, entries inherit the ACL of their parent; the
  default `%TEMP%` is private to the user. The crate does not set
  Windows ACLs itself.
- **Prefixes stay inside the parent.** `with_prefix` rejects a prefix
  containing `/`, `\`, `..`, a NUL byte, or (on Windows) `:`, with
  `io::ErrorKind::InvalidInput`.

## Added

```rust
TempDir::new_in(dir)                      // -> io::Result<TempDir>
TempDir::with_prefix_in(dir, "work")      // -> io::Result<TempDir>
NamedTempFile::new_in(dir)                // -> io::Result<NamedTempFile>
NamedTempFile::with_prefix_in(dir, "x")   // -> io::Result<NamedTempFile>
```

Atomic replace of a config file, with the temp file on the same
filesystem as the target:

```rust
use mod_tempdir::NamedTempFile;

let tmp = NamedTempFile::new_in("/var/lib/app")?;
std::fs::write(tmp.path(), b"new contents")?;
tmp.persist_atomic("/var/lib/app/config.toml")?;
# Ok::<(), std::io::Error>(())
```

## Compatibility

- No public signature changed. Basename formats and the Crockford
  base32 alphabet are unchanged, so `cleanup_orphans` keeps working.
- A prefix with a path separator or `..` is now an error.
- On Unix, other users can no longer read a new temp file or list a
  new temp directory. Grant access explicitly if you relied on it.
- The `mod-rand` feature now enables `mod-rand`'s `tier3` feature
  instead of `tier2`; no new dependency.
- MSRV stays at Rust 1.75.
